# i18n (landing)

Library: `next-intl` (App Router). Locales: `en` (default), `es`.

```
apps/landing/
├── messages/
│   ├── en/{common,home,download}.json
│   └── es/{common,home,download}.json
└── src/
    ├── i18n/
    │   ├── routing.ts      locales + default locale
    │   ├── request.ts      loads and merges the namespaces
    │   └── navigation.ts   locale-aware Link / useRouter / usePathname
    └── app/
        ├── layout.tsx      pass-through root layout (html is in [locale]/layout.tsx)
        ├── page.tsx        `/` redirects to the saved language, or to the default one
        └── [locale]/       pages, receives the locale from the URL
```

The EN/ES buttons (`components/LanguageSwitcher.tsx`) call `router.replace(pathname, { locale })`. All texts change without a full reload.

This app is a static export (`output: "export"`): no middleware, no `proxy.ts`, no server. The default language is `DEFAULT_LOCALE` in `src/i18n/routing.ts`. The language the user picks is saved in localStorage (`LOCALE_STORAGE_KEY`) by `LanguageSwitcher.tsx`, and `/` uses it. `trailingSlash: true` makes pages `en/index.html`, so any static host works without rewrite rules. See [docs/I18N.md](../../../docs/I18N.md#change-the-default-language).

Each page that reads translations calls `setRequestLocale(locale)` so Next.js can pre-render it.

For add-a-namespace and add-a-language steps see [docs/I18N.md](../../../docs/I18N.md).
