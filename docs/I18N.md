# i18n

Rule: **one file per namespace per language.** Never one big JSON.

<!-- scaffold:begin react-apps -->

## Web and desktop (`react-i18next`)

```
apps/<app>/src/i18n/          (web and desktop)
├── index.ts                  i18next config + language detection
├── locales/
│   ├── en/
│   │   ├── common.json       app name, buttons, nav
│   │   ├── home.json         title, greeting, labels of the panels
│   │   └── about.json        content of the About page
│   └── es/
│       ├── common.json
│       ├── home.json
│       └── about.json
└── types.ts                  types for translation keys (from the English files)
```

Use a namespace: `const { t } = useTranslation("home")`. The language is detected from localStorage, then the browser. The EN/ES buttons in the header call `i18n.changeLanguage()` and every text changes without reload.

<!-- scaffold:end react-apps -->
<!-- scaffold:begin landing -->

## Landing (`next-intl`)

```
apps/landing/messages/
├── en/*.json
└── es/*.json
```

`src/i18n/request.ts` merges the namespaces into one messages object. Routes live under `/[locale]` (`/en`, `/es`). Use `useTranslations("home")`.

The landing is a static export, so there is no middleware. `/` is a page (`src/app/page.tsx`) that redirects to the saved language, or to the default one.

<!-- scaffold:end landing -->

## Add a namespace

Example: `settings`.

<!-- scaffold:begin react-apps -->

**Web / desktop**

1. Create `locales/en/settings.json` and `locales/es/settings.json` with the same keys.
2. In `src/i18n/index.ts`: import both files, add `settings` to each language in `resources`, and add `"settings"` to `ns`.
3. In `src/i18n/types.ts`: import the English file and add `settings: typeof settings` to `resources`.
4. Use it: `useTranslation("settings")`.

<!-- scaffold:end react-apps -->
<!-- scaffold:begin landing -->

**Landing**

1. Create `messages/en/settings.json` and `messages/es/settings.json`.
2. Add `"settings"` to the `namespaces` array in `src/i18n/request.ts`.
3. Use it: `useTranslations("settings")`.

<!-- scaffold:end landing -->

## Add a language

Example: `fr`.

<!-- scaffold:begin react-apps -->

**Web / desktop**

1. Create `locales/fr/` with `common.json`, `home.json`, `about.json` (same keys as English).
2. In `src/i18n/index.ts`: import the three files, add `fr` to `resources` and to `languages`.
3. The buttons in `Layout.tsx` are generated from `languages`, so the `FR` button appears.

<!-- scaffold:end react-apps -->
<!-- scaffold:begin landing -->

**Landing**

1. Create `messages/fr/` with one JSON file per namespace (same keys as English).
2. Add `"fr"` to `locales` in `src/i18n/routing.ts`.

<!-- scaffold:end landing -->

## Change the default language

One value per app. Change it and nothing else:

| App     | File                               | Value                                             |
| ------- | ---------------------------------- | ------------------------------------------------- |
| web     | `apps/web/src/i18n/index.ts`       | `DEFAULT_LANGUAGE` <!-- scaffold:line web -->     |
| desktop | `apps/desktop/src/i18n/index.ts`   | `DEFAULT_LANGUAGE` <!-- scaffold:line desktop --> |
| landing | `apps/landing/src/i18n/routing.ts` | `DEFAULT_LOCALE` <!-- scaffold:line landing -->   |

How it behaves:

- **Web / desktop**: the default applies on the first launch. When the user picks a language with the EN/ES buttons, it is saved in localStorage and wins on every later launch. The browser language is **not** used, so the default is predictable. <!-- scaffold:line react-apps -->
- **Landing**: the language is part of the URL (`/es/`), so it stays while the user navigates. When the user picks a language, it is also saved in localStorage (`locale`). `/` redirects to the saved language, or to `DEFAULT_LOCALE` on a first visit. Opening `/en/` or `/es/` directly always wins. <!-- scaffold:line landing -->
- The default must be one of the supported languages (`languages` / `locales`).

## Rules

- Keep the same keys in every language. English is the source of truth for types.
- Group keys by panel or page (`home.title`, `nav.about`), not by "all labels".
- Use interpolation for dynamic values: `"Version {{version}}"` (web) or `"{version}"` (landing/ICU).
